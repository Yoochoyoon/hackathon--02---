## 2. 프롬프트 개선 사례

- 처음 요청: "비주얼 디자인은 https://getdesign.md/apple/design-md 이거로 진행 할 수 있어?"
- 기대와 달랐던 지점: 페이지 자체에는 색상·폰트 같은 실제 스펙 값이 공개돼 있지 않고, `npx getdesign@latest add apple`을 실행해야만 받을 수 있었다. 이는 출처 검증이 안 된 제3자 npm 패키지를 즉시 실행하는 것이라 그대로 진행하기 조심스러웠다.
- 어떻게 고쳤나: AskUserQuestion으로 "검증 안 된 npm 패키지를 임의 실행하는 게 걸린다"고 사용자에게 직접 알리고, 사용자 본인이 터미널에서 `npx getdesign@latest add apple`을 직접 실행하도록 요청했다.
- 고친 뒤 달라진 것: 신뢰할 수 없는 코드를 대신 실행하지 않고도, 사용자가 승인한 방식으로 안전하게 DESIGN.md 스펙을 확보했다.

## 3. 오류 해결 사례

- 오류 메시지 / 증상: 활동명을 비우거나 참여 인원을 0으로 입력해 등록을 시도했을 때, 커스텀 검증 메시지("활동명을 입력해주세요." 등)가 뜨지 않고 이전 검증 메시지가 그대로 남아있거나 아무 반응이 없었다.
- 원인 파악 과정: 브라우저에서 폼을 채워 제출을 반복 테스트한 결과, `<input required>`·`<input min="1">` 같은 HTML5 기본 검증 속성이 우리 JS의 `validate()` 함수보다 먼저 개입해서 `submit` 이벤트 자체가 발생하지 않는 것을 확인했다(네이티브 검증이 막으면 이벤트 리스너가 아예 호출되지 않는다).
- 해결 방법: `<form id="activityForm">`에 `novalidate` 속성을 추가해 네이티브 검증을 끄고, 항상 우리 JS의 `validate()` 로직만 타도록 수정했다.
- 배운 점: HTML5 기본 검증 속성과 커스텀 JS 검증을 같은 필드에 함께 쓰면 브라우저가 먼저 개입해 커스텀 로직이 실행되지 않을 수 있다. 커스텀 검증 메시지를 쓰려면 `novalidate`를 명시적으로 켜야 한다.

## 4. 계획과 달라진 점

- `계획.md`는 선택 기능을 검색 + 반응형 2개로만 잡았으나, 실제로는 월별 통계 차트가 추가돼 3개가 됐다.
- 필수 담당(유초윤) 쪽에도 원래 선택 후보였던 수정 기능·기간 필터가 CRUD 로직 연장선이라는 이유로 넘어왔고, 여기에 활동 유형 태그·참여자 명단·회비 사용 금액·중복 등록 확인까지 추가로 붙었다.
- 비주얼 디자인 방향이 Apple(마케팅 사이트 스펙) → LINE Design System(모바일 앱 컴포넌트 스펙)으로 한 번 바뀌었다. Apple 스펙은 히어로/명암 교차 풀블리드 타일 구조라 폼+목록 유틸리티 앱과 안 맞아 폐기했다.
